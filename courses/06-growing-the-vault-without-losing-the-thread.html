Growing the vault without losing the thread

A linked vault is easy to break and easy to keep. Tonight covers the three habits that decide which: rename notes only where Obsidian can see you do it, run a short maintenance pass once a month so new notes join the network instead of fading out of it, and grow with core plugins while keeping the one layer that lets you walk away, a folder of plain Markdown files. Ines, our constructed researcher, does her first monthly pass at the end.

Part 1 · covers renaming safely

A link is a name, so rename where Obsidian can see

5 min live

A wikilink like [[Notification fatigue]] points at a note by its name, which is its file name on disk. Rename the note inside Obsidian and every link to it is rewritten for you. Rename the same file in Finder, another editor or a sync script, and nothing is rewritten: every link now points at a name that no longer exists.

LiveRename inside Obsidian, and read the one setting3 min▶

The help is direct: renaming a note inside Obsidian, with F2 or by editing the title, updates all links to it. The behaviour sits under Settings, Files and links, in a toggle called Automatically update internal links. The help's own description: "When enabled, Obsidian automatically updates internal links when you rename a file. Turn this off to be prompted to update links after renaming."

Note what "off" means. It does not silently break links; it asks you. Some people prefer the prompt because it shows how many notes a rename touches before it happens. Either way, the rename happens where Obsidian can see it, so the links come along.

LiveWhat an outside rename costs, modelled2 min▶

Session 4's bench, computed on a constructed vault, renamed 20 notes outside Obsidian (four Brightwell interviews, a Corvid findings readout, five reading notes and ten insight notes) and updated no links. On rung 4, idea links plus maps of content, 72 links broke. Mean recall fell from 84.4% to 80.1%, questions answered fell from 11 to 10, and "interviewer bias" dropped from 90.0% to 70.0%, below the 75% line, so it now fails. On rung 3, idea links without maps, 51 links broke and recall fell from 11.5% to 6.5%.

Rungs 1 and 2, folders only and tags only, lost nothing: zero broken links, because folders and tags do not care what a note is called. That is the trade in one line. Links buy reach and cost you a duty of care about names. All of these numbers are modelled on Ines's constructed vault; a real vault will differ.

Self-studyUnresolved links, and the graph filter that shows them3 min▶

A link to a note that does not exist is not an error in Obsidian. It still renders, and clicking it creates the note, which is useful when you are planning and a trap after an outside rename: the click makes a fresh empty note under the old name, and now you have two. Fix the link instead: rename the file back, or edit the link to the new name.

To find them, open the graph view and look at the filter called Existing files only. It shows or hides links to notes that do not exist, so switching it off puts the dangling names on the canvas where you can see them. Check the current help for its exact position; the panels change between releases.

One more setting in the same place: New link format, with Shortest path when possible, Relative path to file, and Absolute path in vault. Shortest path keeps links readable. Absolute or relative paths spell out the folder, which some people want for tools outside Obsidian, at the cost of links that mention folders you may later move.

Real world

The tidy-up that ran in the background. A familiar pattern: someone keeps their vault in a synced folder and, one weekend, runs a bulk renaming tool over it to standardise dates in file names. Every file looks neater in Finder on Monday, and dozens of links across the vault now point at names that no longer exist. Nothing warned them, because nothing that knew about the links was asked.

Part 2 · covers maintenance as a habit

A monthly pass keeps new notes in the network

5 min live

Luhmann did not pretend his slip box ran itself. In his own essay he writes that it "needs a number of years in order to reach critical mass", that until then it functions as "a mere container", and, plainly, that "Some things will get lost". A linked vault has the same failure: notes that never join the network stop being found.

LiveWhy notes fade: Schmidt's black holes2 min▶

Johannes Schmidt, who coordinates the Bielefeld project on Luhmann's card index, describes two kinds of region in it. Hubs are cards with an above-average number of links that give access to large parts of the file. Black holes are poorly linked parts that "tend to remain isolated later on and hence fade away"; some parts seemed untouched since they were written.

Session 4 found the same shape in a constructed vault. On rung 4, the one question the vault could not answer, trust and credibility at 26.9% recall (modelled), failed because its starting interview was never processed: it had no up-link to the map. One missing link put a whole theme out of reach. Luhmann's account is a single self-reported case and the bench is constructed, so neither proves a monthly pass helps; both show how a note goes missing.

LiveThe four stations3 min▶

Orphans. The graph view's Orphans filter shows notes without any links. Each one gets a decision: link it, merge it into a better note, or leave it, because some notes are genuinely standalone.

Unlinked mentions on your maps. Open each map of content and read its unlinked mentions, and do the same for your busiest insight notes. That is where the phrase you have been writing all month without brackets shows up.

Merge or split. The Note composer core plugin merges two notes into one or splits one note into two. Two notes that say the same thing under different titles split their backlinks between them; merging gives the idea one address again.

Link up to a map. Every note made this month gets at least one link up to a map of content. This is the station that matters most, because a new note with no up-link is a black hole on day one.

Self-studyMonthly, weekly, or whenever: the cadence question2 min▶

No controlled study was found on how often a linked vault should be maintained, so "monthly" here is a working default, not a finding. A vault that gains a few notes a week can live with a monthly pass; one that gains dozens may want the link-up station weekly. How a review rhythm fits into the rest of your week, across every tool you use, belongs to PKM ↗.

Real world

The vault that grew for a year without a sweep. A familiar pattern: the first months are careful, every note linked, maps kept up. Then a busy season arrives, notes get written fast and filed nowhere, and a year later the vault holds hundreds of notes the owner half-remembers writing and cannot find. Nothing broke on any single day. Each unlinked note was a small debt, and the interest was paid in searches that came back empty.

Part 3 · covers growing with core plugins and leaving freely

Add on top, keep the bottom layer yours

5 min live

Obsidian keeps adding: daily notes, templates, Canvas, Bases, the graph. Every one of them sits on top of a folder of plain Markdown files that any editor can open. Grow as far up the stack as you like; the bottom layer is what makes leaving possible, and knowing you can leave is what makes it safe to commit.

LiveDaily notes, templates and Canvas3 min▶

Daily notes creates a note named after today's date, YYYY-MM-DD by default, and can start it from a template. Templates fills in variables as it inserts: {{title}}, {{date}} (YYYY-MM-DD by default) and {{time}} (HH:mm), with Moment.js format strings if you want another shape. A daily note that links each new note up to a map makes station 4 of the monthly pass happen as you go.

Canvas lays notes out on an open board and saves a .canvas file in the open JSON Canvas format, so even the board is a readable file. Canvas is for arranging notes you already have; radial mind maps drawn from a central topic are their own craft, in Mind Mapping ↗.

LiveBases, the .obsidian folder, and the cache2 min▶

Bases, a core plugin, gives database-like views of your notes; the data stays in the Markdown files and their properties, and a view is saved as a .base file. Session 3 introduced it. If what you need is a real database for clients, projects and invoices, that work lives in Notion ↗.

Each vault keeps its settings in a hidden .obsidian folder. As a vault grows, resist the urge to tuck a second vault inside it: the help recommends against vaults within vaults because links may not be updated correctly. And if the graph view or outline ever looks out of step with your files, the local metadata cache can be rebuilt under Settings, Files and links; it is rebuilt from the files, so nothing is lost.

Self-studySync, licences, and the local-first exit3 min▶

Sync. Obsidian Sync is a paid service. You do not need it: a vault is a folder, so any folder sync works, and the help names iCloud, Dropbox, OneDrive and Git. Whichever you use, remember Part 1: a sync tool that renames files is renaming outside Obsidian.

Licences. In the help's words, "Obsidian is free to use and is 100.0% user-supported. Organizations can choose to support Obsidian by purchasing Commercial licenses." Sync and Publish are the paid services.

Leaving. Your vault is a folder of .md files, so the exit is copying a folder. What does not travel: block references such as [[Note#^37066d]], which the help says won't work outside Obsidian, and anything that exists only as a plugin's view. Wikilinks travel as readable text, and many tools understand them; if a destination needs standard links, session 1 showed the setting that writes Markdown links instead. Going the other way, opening a single Markdown file from outside the vault needs Obsidian 1.14.

Re-check before you rely on a menu name. The help pages behind this session were read in October 2026, when the latest release was 1.14.4. Obsidian ships changes often, so open the current help and changelog before teaching a setting to someone else or scripting against it.

Build-along

Do the pass on your own vault, with Ines's constructed vault as the worked example. Her counts are placeholders to show the shape of the work; your numbers will differ, and that is the point of counting them.

Check your Files and links settings. Open Settings, then Files and links. Note what each of these is set to before you change anything; check the current help if a name has moved.

Merge two near-duplicate insights with Note composer. Open the weaker note, run Note composer from the command palette and choose to merge it into the stronger one (check the current help for the exact command wording). Write the vault conventions note. One short admin note that tells future you, or Theo, how this vault works. Link it from your top map so it is never an orphan itself.

★ Step 6 · Vault conventions.md--- tags: - admin --- Naming: insight notes are titled as the claim, in a full sentence. Interviews: YYYY-MM-DD <Client> interview P<nn> New notes go to: Inbox, then move or link up within the month. Link-up rule: every new note links up to at least one (map). Renaming: only inside Obsidian. Never in Finder, another editor or a sync script. Monthly pass: orphans, unlinked mentions on each map, merge or split, link up. Last pass: 2026-10-10

Time the pass. Write down how long tonight's pass took. Next month, do it again with the conventions note open and compare. A pass that keeps getting longer is telling you the link-up rule is slipping between passes.

Homework

Before you close the vault

30 min
  1. Put the next monthly pass in your calendar, with a link to your vault conventions note in the event, and write tonight's counts in the note so next month has something to compare against.
  2. Audit anything that touches your vault folder from outside: sync clients, backup tools, scripts, a second editor. For each one, write down whether it can rename files. Anything that can is renaming outside Obsidian.
  3. Make one daily note template that includes a line for linking today's new notes up to a map, using {{date}} in the title or body, and use it for a week.
  4. Rehearse the exit. Copy your vault folder somewhere, open three notes in a plain text editor, and list what still reads well and what does not (block references, plugin-only views). You never have to leave; you should know you can.
Check yourself

Three questions

Clear all three and session 6 gets stamped in your passport.

1 · Ines renames a note in Finder while Obsidian is closed. What happens to the links that pointed at it?

Only a rename made inside Obsidian rewrites links. An outside rename leaves every link on the old name; the link still renders and a click would create an empty note. Modelled on a constructed vault, 20 outside renames broke 72 links on rung 4.

2 · What does turning off "Automatically update internal links" do?

The help says: "Turn this off to be prompted to update links after renaming." Off means asked, not broken. Switching link format is a different setting, Use [[Wikilinks]].

3 · What makes an Obsidian vault portable to other tools?

A vault is a folder of Markdown files on your disk, so leaving is copying a folder. Links live in the notes, not in .obsidian. Block references won't work outside Obsidian, which is the main thing to know before you depend on them.
